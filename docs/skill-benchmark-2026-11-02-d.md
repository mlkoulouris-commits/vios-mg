# Vios skills benchmark — 2026-11-02, fourth pass (the practitioner's seat)

Date: 2026-11-02, late night (after commits 565ddb2 and ca9d373). Scope: the 24 skills in `plugin/vios-core`, `vios-brand`, `vios-journey`, `vios-engage`, `vios-marketing`, their references, `setup/`, `templates/`, `scripts/*.py`, the eleven `evals/` sets and their run logs, `docs/skill-contract.md`, `docs/operating-system.md`, `docs/evals.md`, `docs/sop.md`, `README.md`, `docs/plan.md`, `docs/workflow.md`, `docs/migration.md`, `.gitignore`, `CLAUDE.md`. Method, different from the three earlier passes (which hunted contradictions and pointers): for each plugin its two most-used skills were walked step by step as a new account manager would on day one, with a fresh client folder made by `python scripts/clients.py new` from `templates/client/` on a scratchpad copy of `scripts/`, `setup/` and `templates/` (so the repo stayed untouched), and only the text and the files to go on. Every point where the practitioner would have to guess, ask a colleague or read a second document was written down; every number without a visible owner; every step whose output cannot be checked; every place two documents send two ways. `clients.py new / status / check / facts / pdf` were run on the scratchpad client; `release.py status`, `release.py check` and `clients.py check` on the repo (all OK); the third pass's 13 findings were verified against the current text with `grep`, `git show --stat` and a diff of the front-door card against today's `clients.py status demo-gradina`. No eval was re-run; the logs were read. Read-only except this file.

## Bottom line

Overall: **4.6 / 5** (3.8 → 4.0 → 4.3 → 4.5 → 4.6). Of the third pass's 13 findings, 12 are fixed as written and 1 (cases for the drafting skills) is deferred by design until the first live run; the rate card (first-pass 32) still waits on the owner. The pointer layer is clean: the DEMO card is byte-for-byte today's output, every prompt skips DEMO and ARCHIVED, the report prompt writes its task id, the SOP onboards through setup step 2, the Engagement seed carries the contract's six keys, the three stale eval sets were re-run with a session id.
What the practitioner's seat finds is a different kind of gap, and it is what keeps this under 5: **the text is consistent, but a few of its steps cannot be executed or checked from the files alone.** Two are plain bugs a fresh client hits on day one: the proposal's capacity check counts the DEMO and counts the always-"in progress" Engagement row as a stage in progress, so on 2026-11-02 the first proposal for any new client reads "over capacity, start date moves" (four loop clients against a load of three); and the template's empty first row of `open-facts.md` is counted as an open fact, so a brand-new folder's card says "Open facts: 1" and `clients.py facts` emits an empty task. Three are steps with a hole in them: the three journey skills never say which `status.json` deliverable key (and which of the 6–9 seeded ClickUp tasks) each step moves, and nothing moves the seeded "Stage N sign-off" tasks; the content calendar blocks a client without a Metricool brand while the weekly content run explicitly supports "posting by hand", so the by-hand path is unreachable for a new client; and `signed_off_at` in `qa-log.csv` is "filled by the approver", who is a founder approving in ClickUp and will never edit a CSV in a git repo, so nobody is named to carry the approval across. The rest is small: a PDF cover that says "Deliverable" on every document but the proposal because no skill passes the `Kind` argument that exists; an approver with no e-mail on file when setup step 4 books the calendar invites; "n" columns with no definition of what n counts; a competitor minimum of 5 in one file and 10 in the other; four entry documents (`README.md`, `docs/plan.md`, `docs/workflow.md`, `docs/migration.md`) still describing the three-plugin, Draft→QA, five-task, 22-check, "18:00 / 20:00" department.
Nothing found is a method change. Of the 19 new findings, 15 are S and tonight, 2 are M, 2 wait on a live engagement or the owner.
