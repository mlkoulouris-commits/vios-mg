### 7. Method gaps (services, not client work)

30. **The founder is never asked how it went.** The retrospective is the practitioner's view (`vios-harvest:19` *"Is this the practitioner's view as given?"*); the three handoffs record what was received (`vios-training-programme:104`); no stage sign-off (`vios-engagement-setup:44`) carries a client pulse. Disney Institute and the strategy houses take one question per milestone. Fix: each stage's sign-off step asks the approver one scored question ("would you start the next stage with us tomorrow: yes / with changes / no") and writes it to `status.json › stages › <stage> › pulse`; the harvest reads it beside the KPIs. Effort S.
31. **Nothing reaches the founder between sign-offs.** Setup books sign-off meetings, the retrospective, the thirty-day review and the case window (`:44`); the marketing loop reports monthly; a practice engagement can run four to eight weeks between the Stage 2 and Stage 3 sign-offs with no status line to the client. Fix: a "Send status" route on the front door that turns the card into a four-line note for the approver (what is done, what waits for them, what is open, next date), fortnightly on the calendar. Effort S.
32. **Measure-before-promise depends on an unconfirmed line.** The KPI "today" column reads "measured in week 1" for every new client (`vios-proposal:16`) because the baseline is made at setup, after signature; the only path to a measured "today" at signature is the diagnostic sprint, whose price is "owner to confirm or strike" (`setup/rate-card.md:14`). Until the owner answers open question 1, the practice promises before it measures. Not a skill defect; a decision. Effort user.
33. **No capacity check before a proposal is sent.** `docs/sop.md:37` sets the load (three loop clients, or one engagement plus one loop client per account manager); `vios-proposal` never reads it, so a proposal can be signed into a team that cannot start it. Fix: proposal step 3 shows the account manager's current load from the `account_manager` fields across `clients/*/status.json` and the start date moves when the load is full. Effort S.
