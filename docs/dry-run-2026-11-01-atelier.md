## Method observations

1. **Document-derived answers do not satisfy Move 1.** The archive's diagnosis admits its interview answers were "derived from those documents, not spoken by Evo", and the whole October engagement ran on them. The intake skill should state that Move 1 answers must be the founder's spoken words, that a draft from documents yields the verdict "not ready", and that a rerun on a client with a signed brand book but no recorded interview is not a shortcut: the book is the founder's prior, the interview is still owed.
2. **A rerun needs a rule for the prior book.** Nothing in the intake or diagnosis skill says how to treat an existing signed brand book when the founder asks for the method from scratch. This run treated Brand Book v3 as the founder's prior statement, re-tested each element against the worksheet rules, and left the interview column empty. Suggest the diagnosis skill name this mode: "prior book as hypothesis, interview as evidence".
3. **The archive-as-facts rule works but needs the source column.** Carrying fact sheet and accounts rows with "archive file, date" per row made every unsourced item visible at once (30 open-facts rows from a client the practice has worked with for a month). The guardrails client-file convention could ask for a source column on `fact-sheet.md` by default; the template has one, `accounts.md` does not.
4. **The diagnosis template is thinner than the skill.** `templates/client/diagnosis.md` has seven headings; the skill's output has ten sections plus the Brand Affinity Audit and the second-audience section. The template should match the skill, or the skill should say the template is the minimum.
5. **Partner decisions on founder values.** The October file records a partner deciding (AI ambassador) against a value the founder signed ("Stay human"), with the founder "to be informed". The diagnosis skill's contradiction step caught it only because the archive was read. A line in the guardrails or the persona builder, "a decision that touches a signed value goes back to the founder, not to a Bible footnote", would make it a rule rather than a reading.
6. **One writer at a time was tested for real.** A first attempt to write the files was interrupted when another session restored the old folder mid-run; the Write tool's modified-since-read check stopped every write. The repo rule held because the tooling held, not because anyone checked the sessions list first. Worth adding to `CLAUDE.md`: check `git status` immediately before the first write, not only before editing `plugin/`.

### Method observations

7. **The name skill needs a check mode.** `vios-name-and-tagline` is written for a brand without a name. On a running business the honest run is a check: the existing name enters the long list as the literal it is, a short long list is generated so the test compares rather than ratifies, and ownership is checked for the first time. 8. **The deep interrogation and the diagnosis interview are the same eleven questions.** The diagnosis skill's §3 and §2.1.2.12 ask the same list. On a client where the interview is not yet held, writing `deep-interrogation.md` duplicates the empty table. 9. **A tagline that is also a line to a guest.** The recommended editorial line is the ritual question, so it is both a brand asset (judged by the naming tests) and a guest-facing line (judged by the filter test). 10. **Fresh derivation converged on the same trait.** The filter test derived today from the 2026-11-01 diagnosis landed on the trait the October run found from Brand Book v3 (refusal of the transaction), with different wording and markers. 11. **The persona builder has no "format undecided" state.** Step 2 assumes the client picks a format in the session. Here the format is a founder decision touching a signed value, and the founder is absent. The Bible needed a conditional front page (two formats, one dormant disclosure set, a "nothing with a face ships until decided" rule). The skill should allow that state explicitly, because it will recur whenever the approver and the founder are different people.
12. **Messages were written on an unsigned diagnosis.** The messages skill says "no diagnosis, stop"; it does not say what to do with a diagnosis that is a draft awaiting the founder's voice. This run inherited the draft status into every block and wrote the re-read into the file header. Suggest a line in the skill: a draft diagnosis produces a draft message architecture, headed as such, never copy on top of it.
13. **One writer at a time, again.** `git status` was checked before the first write; the renames from the folder move were staged by another session and were left alone.
